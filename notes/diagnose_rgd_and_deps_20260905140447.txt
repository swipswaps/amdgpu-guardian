*** Device Selection ***

	--database-path, -dbp <path>
		Specify a database path for register, ip, and asic model data.

	--option -O <string>[,<string>,...]
		Enable various flags:
			bits, bitsfull, empty_log, follow, no_follow_ib, no_follow_chained_ib, 
			use_pci, use_colour, read_smc, quiet, no_kernel, verbose, halt_waves,
			disasm_early_term, no_disasm, disasm_anyways, wave64, filter_shader_registers,
			full_shader, skip_gprs, no_fold_vm_decode, force_asic_file, use_full_user_queue, aql_heuristic, no_backtrace

	--gpu, -g <asicname>(@<instance> | =<pcidevice>)
		Select a gpu by ASIC name and either the instance number or the PCI bus identifier.

	--instance, -i <number>
		Select a device instance to investigate. (default: 0)
		The instance is the directory name under /sys/kernel/debug/dri/
		of the card you want to work with.

	--force, -f <number>
		Force a PCIE DID number in hex or asic name.  Useful if amdgpu is
		not loaded or a display is not attached.

	--pci <device>
		Force a specific PCI device using the domain:bus:slot.function format in hex.
		This is useful when more than one GPU is available. If the amdgpu driver is
		loaded the corresponding instance will be automatically detected.

	--by-pci <device>
		Like --pci but still uses the traditional debugfs path to interface with
		the hardware.  This is useful for interacting with APIs that identify hardware
		by the PCI bus address.

	--user-queue, -uq [<clienttype>,]<client>,<queue>
		Attach to a user queue specified by a given client and queue.  Where the optional clienttype is 'kgd' or 'kfd',
		client is one of 'client=number', 'pid=number', or 'comm=string' to select a client by it's
		client number, process PID, or command name, and 'queue' is one of 'queue=number' or 'type=string'.
		For 'type' the string must be one of 'gfx', 'compute', or 'sdma'.

		For example: 'kfd,comm=ollama,queue=2' specifies a KFD client attached to the first instance of ollama and queue #2.

	--gfxoff, -go <0 | 1>
		Enable GFXOFF with a non-zero value or disable with a 0.  Used to control the GFXOFF feature on
		select hardware. Command without parameter will check GFXOFF status.

	--vm-partition, -vmp <-1, 0...n>
		Select a VM partition for all GPUVM accesses.  Default is -1 which
		refers to the 0'th instance of the VM hub which is not the same as
		specifying '0'.  Values above -1 are for ASICs with multiple IP instances.

	--vgpr-granularity, -vgpr <-1, 0...n>
		Specify the VGPR size granularity as a power of 2, e.g., '2' means 4 DWORDs per increment.

	--devcoredump <file>, -dcd <file>
		Initialize a device based on a devcoredump generated by the kernel.

*** Register Access ***

	--lookup, -lu <address_or_regname> <value>
		Look up bit decoding of an MMIO register by address (with 0x prefix) or by register name.
		The register name string must include the ipname, e.g., uvd6.mmUVD_CONTEXT_ID.

	--write, -w <address_or_regname> <number>
		Write a value in hex to a register specified as a register path in the
		form <asicname.ipname.regname>.  For instance "tonga.uvd5.mmUVD_SOFT_RESET".
		Can be used multiple times to set multiple registers.  You can
		specify * for asicname and/or ipname to simplify scripts.
		When using an address directly use the BYTE address of the register.
		Ex (write via regspec name): umr -w *.*.mmUVD_SOFT_RESET 0x11223344
		Ex (write via byte address): umr -w 0x1014 0x55667788

	--writebit, -wb <string> <number>
		Write a value in hex to a register bitfield specified as in --write but
		the addition of the bitfield name.  For instance: "*.gfx80.mmRLC_PG_CNTL.PG_OVERRIDE"

	--read, -r <address_or_regname> <number>
		Read a value from a register and print it to stdout.  This command
		uses the same path notation as --write.  It also accepts * for regname.
		A trailing * on a regname will read any register that has a name that contains the
		remainder of the name specified.
		When using an address directly use the BYTE address of the register.
		Ex (read via regspec name): umr -r *.*.mmUVD_SOFT_RESET
		Ex (read via byte address): umr -r 0x1014

	--logscan, -ls
		Read and display contents of the MMIO register log (usually specified with
		'-O bits,empty_log' to continually dump bitfields and empty the trace after.)

*** Device Utilization ***

	--top, -t
		Summarize GPU utilization.  Can select a SE block with --bank.  Can use
		options 'use_colour' to colourize output and 'use_pci' to improve efficiency.

	--waves, -wa [all=][<none> | <uq> | <ring_name> | <vmid>@<addr>.<size>]
		Print out information about any active CU waves.  Can use '-O bits'
		to see decoding of various wave fields.  Can use the '-O halt_waves' option
		to halt the SQ while reading registers.  An optional ring name can be specified
		which will then search a given ring for pointers to active shaders.  It will
		default to the 'gfx' ring if nothing is specified.  An IB can be specified
		by a vmid, address, and size (in hex bytes) triplet.  Using user queues can
		be specified by passing 'uq'.  Specifying 'all=' will scan all of the GFX (XCD) blocks in the ASIC.

	--singlestep, -ss <se>,<sh>,<wgp>,<simd>,<wave>
		Single-step one wave.
		Tries advancing execution on the specified wave by one instruction.
	--profiler, -prof [pixel= | vertex= | compute=]<nsamples> [ring]
		Capture 'nsamples' samples of wave data. Optionally specify a ring to search
		for IBs that point to shaders.  Defaults to 'gfx'.  Additionally, the type
		of shader can be selected for as well to only profile a given type.

*** Virtual Memory Access ***

	VMIDs are specified in umr as 16 bit numbers where the lower 8 bits
	indicate the hardware VMID and the upper 8 bits indicate the which VM space to use.

		0 - GFX hub
		1 - MM hub
		2 - VC0 hub
		3 - VC1 hub

	For instance, 0x107 would specify the 7'th VMID on the MM hub.

	--vm-decode, -vm vmid@<address>
		Decode a page mapping at a specified address (in hex) from the VMID specified.
		The VMID can be specified in hexadecimal (with leading '0x') or in decimal.
		Implies '-O verbose' for the duration of the command so does not require it
		to be manually specified.

	--vm-read, -vr [<vmid>@]<address> <size>
		Read 'size' bytes (in hex) from a given address (in hex) to stdout. Optionally
		specify the VMID (in decimal or in hex with a '0x' prefix) treating the address
		as a virtual address instead.  Can use 'verbose' option to print out PDE/PTE
		decodings.

	--vm-write, -vw [<vmid>@]<address> <size>
		Write 'size' bytes (in hex) to a given address (in hex) from stdin.

	--vm-write-word, -vww [<vmid>@]<address> <word>
		Write a 32-bit word 'data' (in hex) to a given address (in hex) in host machine order.

	--vm-disasm, -vdis [<vmid>@]<address> <size>
		Disassemble 'size' bytes (in hex) from a given address (in hex).  The size can
		be specified as zero to have umr try and compute the shader size.

		MES packets, '1' for VPE packets, '5' for UMSCH packets, '6' for HSA packets, '7' for VCN decode, and '8' for
